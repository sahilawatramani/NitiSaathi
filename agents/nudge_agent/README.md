# NitiSaathi — Nudge Agent

The Nudge Agent is a proactive financial coaching service for gig workers. It evaluates user transaction data and features (generated by the `data_pipeline`) to identify actionable financial trigger states, formats appropriate advisory notifications, and simplifies them for the user using the **Literacy Agent**.

---

## Architecture & Design

The agent follows an **agent-agnostic trigger registry pattern**:
* **Abstract Base Class (`TriggerChecker`)**: Defines the standard interface for any financial nudge.
* **Loose Coupling**: Triggers reside in their own self-contained checkers (e.g., `LowBalanceBeforeDebitChecker`). The core orchestration engine loop queries the checkers blindly.
* **Easy Extensibility**: To add a new trigger type, a developer simply implements a new subclass of `TriggerChecker` and registers it by appending it to the module-level `TRIGGER_REGISTRY` list. No modifications to routing, main orchestration loops, or suppression handling are needed.
* **Graceful Degradation**:
  * If a checker fails to load features or has missing data, it returns `None`, causing the system to skip the nudge silently instead of crashing.
  * If the Literacy Agent service is down or fails, message simplification falls back to the raw plain-English message.
* **Suppression Control**: If a user flags a nudge as "harmful" once, or "not_useful" 3 consecutive times, the corresponding trigger is suppressed for that user.

---

## API Endpoints

* **`GET /nudges/run-check`**: Runs checks for all users in the system, simplifies messages, and returns a list of active `NudgeOut` objects.
* **`POST /nudges/feedback`**: Accepts user feedback (`{user_id, trigger_id, rating}`) and stores it in the suppression tracking system.

## Running Locally

To run the Nudge Agent server locally on port `8004`:

1. Ensure the virtual environment is activated:
   ```bash
   # On Windows:
   .\myenv\Scripts\Activate.ps1
   ```
2. Run the application using Uvicorn:
   ```bash
   uvicorn agents.nudge_agent.main:app --reload --port 8004
   ```
3. Open Swagger documentation at: `http://127.0.0.1:8004/docs`

## How to Add a New Trigger Type

To add a new trigger type, follow these two simple steps in `agents/nudge_agent/services/trigger_registry.py`:

1. Implement a new class inheriting from `TriggerChecker`:
   ```python
   class HighEmiBurdenChecker(TriggerChecker):
       trigger_id = "high_emi_burden"
       source = "budget_agent"

       def check(self, user_id: str) -> Optional[bool]:
           # Look up emi_burden_pct in features.csv, return True if > 0.40
           ...

       def build_message(self, user_id: str) -> str:
           return "Your monthly EMI burden is very high. Consider refinancing options."
   ```
2. Add an instance of your new checker class to the `TRIGGER_REGISTRY` list:
   ```python
   TRIGGER_REGISTRY.append(HighEmiBurdenChecker())
   ```
   *The core orchestration loop will automatically pick it up and evaluate it.*
